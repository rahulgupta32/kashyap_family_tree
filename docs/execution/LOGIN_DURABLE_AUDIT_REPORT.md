# Durable OTP-login audit — 2026-10-10

OTP login previously created a session and signed tokens before a direct audit append; a swallowed append failure left no durable login evidence. Session creation and LOGIN audit-outbox insertion now share one PostgreSQL transaction. SessionRepository accepts its transaction client; JWT signing and response/cookie issuance occur only after confirmed commit. Missing database/outbox dependencies refuse verification before OTP consumption, including test environments. No runtime unaudited fallback is enabled.

An outbox insertion/transaction failure returns a generic 503 without tokens or a refresh cookie. PostgreSQL rolls back the session on insertion failure. A lost commit acknowledgement returns no credentials and leaves any actually committed session plus matching intent intact; it does not falsely claim rollback or delete potentially committed evidence. The OTP has already been consumed, so a fresh code is required. Account lookup/phone-verification/default-role setup precede this transaction and are not claimed rolled back by this change.

Only the new login intent is attempted for immediate audit delivery. Downstream delivery failure keeps the committed session usable and the durable intent retryable with fixed LOGIN_AUDIT_DELIVERY_FAILED metadata; no downstream error text is copied into the response or login warning. Existing outbox processing deduplicates append delivery by outbox ID. Delivery retries/draining still need operational monitoring; this change does not establish a new background worker.

The login event payload contains role IDs and the session ID; it omits the phone number, OTP, access token, refresh token and device label. Existing actor/account IDs and request IP/user-agent remain access-controlled audit metadata governed by the privacy/retention policy. Do not interpret this as anonymous auditing.

Four unit regressions cover insertion rollback/no signing, uncertain commit/no signing, delivery failure/retry metadata and missing dependencies without OTP consumption. Three real PostgreSQL/HTTP regressions cover durable insertion/delivery outage/exactly-once recovery, rollback/no cookie/consumed OTP/fresh login, and deliberately lost acknowledgement after real commit. Local and CI results are recorded in PR #5; new exact-head database/browser/Android checks must pass before verification is claimed.

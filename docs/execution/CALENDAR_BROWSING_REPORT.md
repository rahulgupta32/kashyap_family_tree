# Bounded complete calendar browsing checkpoint

The original management list is bounded to 100 events. Migration 035 adds a unique bigint ingestion sequence and an authenticated `/calendar/browse` route, providing pages of at most 50 with an exact string cursor. Existing rows receive deterministic sequence order from their retained creation timestamp/ID; later submissions receive increasing sequences. The browser orders submissions, not converted occurrence dates. Numeric ordering and strict positive signed-bigint cursor validation avoid text sorting and JavaScript precision loss. Concurrent new submissions do not shift an older-page boundary. Rollback drops only this browsing index metadata, invalidating issued cursors without removing event data.

Each page uses the existing current event visibility expression, including branch, family and nonrevoked invitation checks and existing super-administrator authority. Detail projection preserves existing organizer-only attendee IDs/counts and viewer RSVP. Filters accept supported BS years/months, branch UUID and known audience scopes. BS filters match stored solar/Tithi source metadata; AD events are not inferred into BS periods. Reading does not change event versions, stored dates, provenance, invitations or reminder state. This does not create authoritative Tithi/AD conversions or recurring family reminders.

Web exposes a separate all-event browser with BS year/month filters, older/latest controls, bounded empty/error/loading states and original source-date labels. The management list explicitly states its 100-event limit. Flutter exposes the same browser from the calendar toolbar, with source filters, older/latest/retry controls and unavailable Tithi conversion labels. Changing filters clears stale results and pagination boundaries. Management, invitation, RSVP and organizer workflows remain in the existing event list; the new browser is read-only.

Two new real PostgreSQL HTTP cases cover 105-event traversal without overlap, concurrent insertion, hidden/revoked private invitations, host access, authentication, cursor/filter validation and source/provenance preservation. A unit case checks invalid cursors/filters before persistence. The live browser scenario browses the updated cancelled event and filters out its AD source. A mocked native test preserves a cursor above the JavaScript safe-integer range and resets pagination when applying a source filter. Dedicated browsing device/load/accessibility acceptance is not claimed.

Local typechecks, API/admin production builds, the existing 166-test unit run plus the updated eleven-test calendar suite, 31-scenario browser collection, frozen assessment validation and diff checks passed. Exact published-head CI is pending at initial publication; final verification will be recorded in PR #5.

All 260 original acceptance fields and 31 exact frozen NFR targets remain unchanged/open. Historical assessment is not globally reclassified. CAL-FR-010 remains partial: complete day/month/agenda presentation and signed conversion/recurrence references remain mandatory. Larger calendar audiences, follower notifications, approved calendar sources, production provider/device/load/security/accessibility/recovery/authority acceptance and other release scope remain open. No merge or deployment.

# Public authentication, portal authority and disposable restore — 2026-10-10

Owner: Jyphra Technology Pvt. Ltd. This advances mandatory release work; it does not authorize production release or close the original acceptance ledger.

## Credential and authority boundaries

Both browser and native refresh routes now share the existing Redis-backed public-auth admission window with OTP request/verification: sixty combined requests per network per minute, before validation, session rotation and audit writes. Excess requests return 429 with Retry-After; unavailable/invalid Redis admission returns fixed bilingual 503 without rotation. Test fixtures explicitly bypass this limiter in NODE_ENV=test; dedicated HTTP cases activate it outside test mode. Trusted proxy/NAT design, distributed-source abuse, production ingress and measured capacity budgets remain required. The internal key name is preserved to avoid resetting an existing window on rollout.

Logout and logout-all require the database and durable outbox. The session mutation and LOGOUT intent share the PostgreSQL transaction. Insertion failure rolls back revocation; an unconfirmed commit returns fixed bilingual 503 without claiming logout success or deleting potentially committed evidence. The caller may need to retry logout or reauthenticate. Immediate delivery failure preserves confirmed revocation, records a fixed retry error and retains scheduling. The request attempts only its own audit event; it no longer drains an unrelated backlog. The scheduled worker remains responsible for that backlog. Logout token validation and delivery diagnostics no longer include raw exception text.

Branch administrators cannot assign or revoke CENTRAL_ADMIN, including a historically branch-scoped central record. This closes the previously omitted administrative-role boundary. Super Admin remains the only role permitted to grant administrative authority; self-elevation and current-role/branch checks remain enforced. No previously retained role assignment is silently rewritten or deleted. Existing historical grants require governed review; engineering does not infer approval from an existing database record.

## Portal and accessibility

The normal sign-in path and restored-session admin classification recognize current CENTRAL_ADMIN alongside SUPER_ADMIN and BRANCH_ADMIN. Backend permission checks remain authoritative; UI classification does not grant Super Admin role-management privileges.

Phone/OTP labels are associated with inputs; helpers and error alerts are linked, invalid states announced, and input modes/autofill are supplied. Browser scenarios exercise keyboard submission, error state, OTP focus, denied-access focus/reset and actual central-admin sign-in/restoration/current API permissions. This is bounded accessibility evidence, not a complete WCAG 2.2 AA/manual assistive-technology/mobile acceptance claim.

## Executable disposable logical restore

`scripts/verify-disposable-restore.cjs` requires explicit test mode, a selected disposable PostgreSQL service container and a loopback connection. It generates its own source/target database names and never selects a caller-provided application database. It applies the full migration stack, seeds fictional genealogy/accounts/session/evidence, performs an actual PostgreSQL custom-format dump/restore, and compares all public table contents plus constraint/index/trigger/sequence manifests. It verifies audit-chain integrity and a subsequent append, immutable audit protection, self-parent rejection and retained failed-outbox retry scheduling. Cleanup drops only the generated databases and removes its private temporary archive; cleanup failure fails the gate. No credentials, row payloads or raw SQL/dump errors are placed in the JSON report.

The platform CI job runs the rehearsal and retains its JSON evidence. The report explicitly sets production acceptance, PITR and production RPO/RTO verification to false. A tiny fictional logical restore is not production-like managed backup/PITR, object-storage/key recovery, scale/RTO, scheduled quarterly rehearsal or incident/rollback acceptance. Those remain mandatory; the measured fixture duration is not a production SLA. No production host, provider, credentials or deployment is configured by this checkpoint.

# Community revision checkpoint — 2026-10-04

Author-only `PUT /community/posts/:id` accepts title, content, category, viewed version and a 5–1000 character edit reason. Branch/identity/status fields are refused. Current verified membership and branch access are checked against the locked post. Moderators cannot rewrite another author's content. Announcement authority is rechecked. Stale edits fail with 409; identical normalized content changes nothing.

Changed text/category becomes PENDING, increments the version and retains a snapshot in migration 029's revision table. Post, snapshot and durable audit intent commit together. Publication uses the new post version and still requires an independent scoped moderator; previous content approval cannot publish an unseen edit. Pending content is hidden from ordinary readers and cannot receive reactions/comments.

`GET /community/posts/:id/revisions?page=1` returns at most 50 descending snapshots. Only the author or currently authorized scoped moderator can read them, including when the current post is published. Deleted posts return 404 and history remains retained in the database. The read locks the post through authorization and selection. Editor account IDs are omitted. Web and Flutter provide edit reason, history, pagination and re-review guidance, and retain the draft when an API error occurs on web. Native editor returns a draft to the parent before sending, matching the existing composer; durable offline community drafts remain future work.

New posts record the initial submission. Existing posts receive their current content/version snapshot at rollout; missing historical edits are not invented. Version gaps represent moderation/report actions without a content change. The migration does not alter lineage or remove prior post/comment/report data. The down migration drops history and requires separately approved destructive rollback with an export first.

Verification added: isolated real PostgreSQL HTTP tests for restricted history, stale publication, concurrent edits with one winning revision, no-op edits, persistence across service recreation, audit rollback and deleted-history refusal. Existing live Playwright community workflow now edits a published post, reads both snapshots and republishes through a second account. Flutter mocked HTTP/widget tests verify version/reason payload, pending state and retained snapshots. Unit validation checks reject malformed requests before persistence. Exact-head CI will be recorded in PR #5.

# Governed exhausted audit recovery

Owner: Jyphra Technology Pvt. Ltd. This is bounded release work, not production acceptance.

## Behavior

Audit delivery continues to stop automatically after ten failed attempts. A current Super Admin with fresh session and verified current authenticator can propose one recovery attempt for an exhausted retained event. A different current Super Admin with the same authentication requirements must approve it within 24 hours. The proposing administrator must still hold active Super Admin authority when approval executes. Branch/Central Admin authority alone is insufficient. These recovery operations require MFA in every environment, including fictional fixtures.

Fixed reasons are dependency recovery or repaired delivery configuration. Neither free text nor original event payloads, identities, network details or raw delivery errors are exposed in the review list. Lists return bounded twenty-row metadata views; broader paging and incident navigation remain required. The web controls use associated labels, status/error announcements, a working authenticator link and bounded bilingual recovery text. Self/expired approval controls are disabled; backend authorization remains authoritative. Changes in credentials/account clear pending view requests, and failed actions clear stale evidence rather than show a successful recovery.

Migration 051 stores immutable proposals and decisions. Proposal insertion and its redacted audit intent commit together. Approval locks the proposal and retained event; a savepoint isolates the single manual delivery attempt. SQL delivery failure rolls back that attempt while recording a fixed failed outcome. Original retry count and failure evidence are never reset, and failure does not reopen automatic delivery. Successful append, decision and redacted outcome intent commit together; outcome-intent insertion failure rolls everything back. Unconfirmed acknowledgement returns fixed 503; duplicate commands can recover a persisted proposal/decision without redelivery. A processed event cannot be revived. Database rollback refuses to erase retained recovery evidence.

An explicit recovery proposal permits exactly one supervised attempt, not an automatic retry budget extension or a successful-delivery assertion. Worker outages can still delay the recovery action's own audit-log delivery; immutable recovery rows and outbox intents remain retained. Database owners can bypass application policy and require production least-privilege controls and independent review. Named approvers, human incident procedures, fleet alerts and incident acceptance remain external release work.

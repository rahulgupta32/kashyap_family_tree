# Community image checkpoint

Migration 032 adds one current scanned image per post, immutable upload request IDs and retained revision/media links. Authors can attach PNG/JPEG/WebP up to 5 MiB to an existing post using the viewed version and a reason. Changing media withdraws open appeals, increments the version, records a content/media snapshot and returns the post to PENDING independent review. Removal retains original evidence and prior revision links. Historical images are readable only by the author/currently scoped moderators on an undeleted visible post.

Scanner infection/outage, invalid formats/base64/dimensions, impersonation, foreign branches, stale edits and competing current images fail closed. Retry uses the original ID, file, reason and version, including after later moderation. Upload journals, private storage, exact checksums, bounded image jobs and metadata-stripped WebP derivatives reuse existing infrastructure. Commit uncertainty retains possibly committed bytes. Original download is author/scoped-moderator only; ordinary authorized feed readers obtain display/thumbnail derivatives only. Every download rechecks owning-post visibility and asset scan/retention under locks and uses no-store/nosniff attachment headers. Deleted posts disclose no media; legal/retention evidence is preserved.

A separate private-community storage prefix and bounded local directory are included in inventory and image repair. New inventories include the community prefix; the physical storage scope fingerprint and prior upload journals remain stable. Migration rollback refuses retained community media. Development local files and existing originals/backups remain intact.

Web and Flutter expose image selection, change reasons, independent review guidance, download/removal and processing retries. Failed upload forms retain immutable request payloads for explicit retries. Native file selection/save reuses the Android document bridge; other native platform file-picker acceptance and durable offline image intent remain open. Revision screens provide image downloads for authorized history.

Coverage: local storage directory/inventory regression; real PostgreSQL HTTP concurrent replay, privacy/current-version checks, metadata stripping, revision retention, deletion, scanner failure/infection and audit rollback; live browser upload/re-review/original download; mocked native HTTP upload retry; a dedicated real S3/PostgreSQL community image/derivative/journal/privacy case. General integration skips dedicated storage cases, which run separately. Exact-head CI results will be recorded in PR #5; pending at initial publication.

All 260 original acceptance fields and 31 frozen NFR targets remain unchanged/open. This bounded image checkpoint does not close COM-FR-002/010/013 or global production acceptance. Multiple images, video/other media, privacy-controlled location/contact fields, configurable moderation policy, richer case workflows, approved retention policy and production provider/device/load/security/authority acceptance remain mandatory. No merge, deployment or real-user migration is performed.

# Exact administrative lookup — 2026-10-08

`GET /admin/lookup?type=PERSON|USER|CLAIM|CHANGE_REQUEST&id=<UUID>` supplies exact primary-key lookup from one web portal. Strict type/UUID/query validation rejects partial IDs, unknown types and forged actor fields. The existing JWT guard derives the actor's current roles, branches, account status, session age and required authenticator proof from PostgreSQL.

Super/Central Admin, Branch Admin and Branch Verifier may enter the lookup workflow. Account lookup requires central administrative authority and returns only account ID/status, verification flag, linked Person ID, creation time and role/branch labels. Phone numbers, suspension reasons, preferences, tokens, credential material and sessions are excluded. Deleted accounts return 404. Branch Person lookup checks current administrative branch assignments before reading and again after canonical resolution. Person projection uses the existing privacy engine. Claim and change-request reads delegate to existing governed detail services with the authenticated actor, retaining their finer review/evidence permissions. A Central Admin role does not invent claim-review authority where the existing service requires Super Admin or specific branch reviewer authority. Out-of-scope and missing target records share a 404 response.

Successful reads require durable `ADMIN_EXACT_ID_LOOKUP` audit intent before returning. Audit records retain actor, type and target ID, not response contents. Audit storage failure returns no lookup data. Responses use no-store. UI selectors, exact-ID validation, bilingual summaries, person/review links and stale-result clearing support the workflow. Session/token epochs reject late responses from superseded sessions/requests. A fixed `/login?next=/lookup` entry allows current lookup roles through phone login and the existing MFA screen without arbitrary external redirects or role elevation.

Local API/admin typechecks/builds and existing unit suite are checked. Four dedicated PostgreSQL scenarios cover all four types/minimal account output, current roles/branch permissions, malformed/missing inputs and audit failure. One browser scenario verifies account lookup and clearing previously found results on a missing ID. Exact-head CI is pending until final results are recorded in PR #5.

SRCH-FR-008 now has partial implementation evidence; it is not signed acceptance. Dedicated device/broader workflow, accessibility and production load/security acceptance remain. This feature does not implement transliteration, genealogy imports, administrative configuration, genealogy audience derivation or production infrastructure. All original release acceptance remains open.

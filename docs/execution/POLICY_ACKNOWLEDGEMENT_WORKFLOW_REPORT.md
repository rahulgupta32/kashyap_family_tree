# F1 policy acknowledgement workflow

Requirement context: PRIV-FR-006 (versioned policy acknowledgements with user acceptance timestamp), AUTH/PROF account separation, NFR-REL-001 and audit/privacy controls. This is the first cross-layer implementation in F1, not completion of its44 assigned requirements or optional-consent withdrawal EC-0032. Existing optional privacy/preferences/withdrawal controls are unchanged. No legal text, lawful basis, mandatory-processing consent or collection permission is invented.

Migration061 creates immutable bilingual policy documents with positive per-kind versions, effective/expiry bounds, database-generated SHA256 over exact content, approver-account/reference provenance and immutable account/document/hash/time receipts. Nothing is seeded or backfilled. There is no policy publication HTTP endpoint. Real text, approval validation/publication/retirement process, legal/retention/guardian decisions and policy enforcement remain owner/review gates. An empty approved catalogue is explicitly unavailable; it is never shown as accepted or used to authorize new processing. This does not enforce mandatory acknowledgement at sign-in.

Authenticated GET /me/policies (also profile controller alias) returns only effective latest-version content and the current account's receipt status plus20 metadata history records. An expired latest document does not resurrect an older version; future versions stay hidden. Account must be active, unsuspended and not deleted. Private/no-store headers apply. POST /me/policies/acknowledgements accepts only documentId, exact contentHash and accepted:true; actor and timestamp come from server context. Unknown fields/account injection/false acknowledgement/malformed IDs/hashes fail before mutation. Wrong content and new acknowledgement of stale/future/expired policy fail409. Historical response-loss replay returns the original own receipt with current:false when superseded, without claiming current acceptance.

Receipt creation and audit-only outbox intent are one transaction. Account row SHARE lock prevents concurrent suspension/deletion changes during the operation. Policy table SHARE lock permits concurrent acknowledgements while blocking publication writes across current-version check/commit. Unique account/document key coalesces concurrent retries; only the insert winner emits audit. SHA mismatch cannot be stored. Finalized content/receipts cannot be updated/deleted; down migration refuses retained evidence. Database-owner privileges and independent retention/legal operations remain external review boundaries, as with other evidence tables.

Admin /policies and mobile Policies navigation display bilingual plain text, require a separate explicit checkbox for each version, send exact ID/hash without account/time overrides, and show acknowledgement only after authoritative reload. Lost-response retries keep the same content identity; generic errors never echo diagnostics. Synchronous single-flight/generation guards prevent repeated or stale-account actions; new scope/unmount clears pending UI identity and stale callbacks cannot submit. Same-session rotation is conservatively reloaded on web; native keeps the existing session-generation semantics. Stable policy label keys are externalized. Approved-document history is available from API; full historical-document inspection and global locale preference are not added here.

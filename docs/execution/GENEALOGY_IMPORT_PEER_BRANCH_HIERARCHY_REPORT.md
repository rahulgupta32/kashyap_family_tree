# Cross-batch source-branch hierarchy reconciliation

ADM-FR-013 remains partial. Validator `staging-15-peer-branches` extends the existing same-dataset/same-catalogue-branch, 50-peer dry-run snapshot with source-only branch hierarchy checks. A current branch parent reference, Person source-metadata branch reference, or evidence-source branch reference can resolve to exactly one retained peer source branch. Local dangling issues are removed only for that unique source identity. A peer source branch with an absent parent, duplicated peer source IDs, or a cycle spanning peer batches produces a blocking issue. A cycle involving the current batch identifies only its current branch source IDs; a peer-only cycle uses the current dataset key. Peer branch identifiers, names, authority claims and source values are not copied into the report or audit intent.

The graph traversal is iterative and bounded by the pre-existing 50 peer batches and 200 branches per batch. An erased or over-limit peer prevents reference resolution. Existing repeated-ID checks, immutable hashes, prior reports, current verified Super Admin authorization and explicit branch authority review continue to apply. This compares staged source hierarchy only; it cannot map source branches onto accepted target branches or approve any claimed status or authority. `promotionAllowed` stays false and no accepted branches, Persons, claims or relationships are written.

Four new unit cases cover split references, a cross-batch cycle, peer-only cycle and missing parent privacy, and ambiguous identities. A real-PostgreSQL case stages a three-batch cycle, inspects the intermediate and current reports, checks source-only output, erases a peer, and verifies live branches and Persons do not change. Locally, API TypeScript typecheck, 52 focused import unit tests, and whitespace checking pass. Real PostgreSQL cannot be reached from this sandbox; exact-head CI must verify the integration case before this batch is considered fully checked.

Remaining work includes approved workbook transforms, authoritative source/branch decisions, reconciliation across accepted target branch hierarchy and later source revisions, governed promotion/recovery rehearsals, and all frozen release gates. This change is not approval to import real genealogy or deploy.

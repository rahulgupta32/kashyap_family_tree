# Source calendar day/month/agenda checkpoint

Authenticated `/calendar/period` selects an AD or BS source date and DAY, MONTH or AGENDA view. Gregorian periods use PostgreSQL Asia/Kathmandu timezone boundaries, including historical timezone rules, rather than the viewer browser/device timezone. BS selection validates against the existing frozen supported year/month data. Source selection does not convert the event or typed date. The existing BS data/helper is reused; no new authoritative calendar/Tithi source or signed acceptance is introduced.

Day reads match exact stored BS dates or the half-open Nepal Gregorian day. Month/agenda reads match the corresponding stored source month. BS Tithi-only records in that source month retain a null display date and appear last in an undated group; they never receive an invented day. AD source periods do not include inferred BS/Tithi dates. Previous/next day or month selection respects supported source boundaries. Gregorian leap-day and month/year transitions are explicit.

Period summaries return zero-filled day counts for the full authorized period, independently of the first 50 event records, plus an undated count. Each summary/page query reuses current event visibility, including branch/family/invitation/revocation and existing super-administrator scope. Detail projection retains existing organizer-only roster/count rules. Event pages sort by source display date, then decreasing bigint ingestion sequence, placing undated records last. Validated composite cursors preserve exact bigint values and reject other source periods. Pagination traverses days and the undated group without overlap. Summary and record queries are current database reads, not a frozen cross-request snapshot; concurrent changes can change counts. Reads do not rewrite event provenance/version/calendar values or send notices.

Web and Flutter expose source/view/date selection, previous/next navigation, selectable numbered month days, grouped day/agenda records, explicit unavailable-conversion guidance, full-period counts and bounded first/more event navigation. BS cells are numbered days without unapproved weekday conversion. The new presentation is read-only; management and RSVP remain in the existing event controls. Web account changes clear/invalidate previous responses. Errors retain inputs for explicit resubmission. Both clients use server-projected source display dates.

Three unit cases cover Gregorian leap-day/period transitions, supported source boundaries, invalid representations and exact composite cursors. Two PostgreSQL HTTP cases cover Nepal midnight/exclusive-end selection, full counts and private invitation revocation, ordered multi-page BS month traversal, unconverted Tithi placement and invalid source/date/cursor requests. The live browser scenario opens a month day and agenda for the updated cancelled event. One mocked native case checks month-to-day navigation, agenda selection and a composite cursor above JavaScript safe-integer precision. Dedicated calendar-view device, load and accessibility acceptance is not claimed.

Local API/admin typechecks and production builds, 170 unit tests, 31-scenario browser collection, frozen assessment validation and diff checks passed. Exact published-head CI is pending at initial publication; verified results will be recorded in PR #5.

Signed calendar/conversion/recurrence references, derived family reminders, broader audiences/follower notices, full bilingual/accessibility/device/load/security/provider/recovery/authority acceptance and other mandatory release work remain open.

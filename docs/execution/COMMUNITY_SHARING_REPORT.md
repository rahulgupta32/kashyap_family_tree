# Community location/contact sharing checkpoint

Migration 033 adds optional approximate locality labels, separate locality/contact visibility and explicit post contact consent. Existing and new posts default to PRIVATE with no locality and no consent. There are no coordinate/street-address or caller-supplied contact fields. Locality accepts bounded Unicode district/municipality names; digits, coordinate keys, house numbers and arbitrary extra fields fail validation. Place labels require independent human review; this does not establish an authoritative geographic registry or infer that free text elsewhere is coarse.

Authors change sharing using the viewed post version and a reason. Announcement authority is rechecked. Changed fields withdraw open appeals, increment the post version, retain a revision and return the post to PENDING independent moderation. Normalized unchanged settings preserve state. Competing requests serialize and audit failure rolls back all changes. Revision history retains labels/consent metadata for the author and scoped moderators; phone numbers are not automatically copied to revisions or audit/delivery payloads.

Feed projection uses current author account/profile/person data. Non-reviewers receive locality only for a published explicitly shared post, active unsuspended undeleted author, current claimed living unarchived adult profile and account/person address settings permitting verified-community visibility. Authors and scoped moderators can inspect submitted coarse labels for review. Shared phone similarly requires published explicit post consent, current account/person contact privacy allowing verified visibility and an established adult claimed profile. No administrator bypass reveals phone numbers of protected or uncertain-age profiles. The existing frozen calendar/age protection helper is reused; no new age/calendar source is introduced. Withdrawal of profile or post consent, suspension/archive/minor protection or uncertain age hides the corresponding fields on subsequent reads. Existing owning-post branch/membership/moderation/deletion checks apply. Users cannot submit another person's contact number through the sharing route.

Web and Flutter offer separate sharing switches, private defaults, district/municipality and reason fields, review guidance and warnings about intersecting profile privacy. Feed fields use the server-filtered projection. Revision screens show retained locality/consent metadata. Three real PostgreSQL cases cover defaults/revocation/protected-profile projection, invalid precise/contact payloads, authorization, stale edits, no-op state, concurrent changes and audit rollback. The live browser scenario edits/reviews private locality; a mocked Flutter test checks private defaults, explicit locality consent and viewed-version/no-phone request shape. Dedicated sharing device/provider acceptance is not claimed.

Local API/admin typechecks, 165 unit tests, 31-scenario browser collection, frozen assessment validation and diff checks passed. Exact published-head CI is pending at initial publication; verified results will be recorded in PR #5.

All 260 original acceptance fields and 31 exact frozen NFR targets remain unchanged/open; historical assessment classification is not globally revised. This checkpoint does not close COM-FR-002 or global privacy acceptance. Broader family audiences, authoritative geography, free-text abuse/contact/location handling, configurable moderation policy, fuller case workflows, other media and production provider/device/load/security/authority/retention acceptance remain mandatory. No merge or deployment.

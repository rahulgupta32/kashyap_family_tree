# Private chat attachment checkpoint

Migration 023 links one media asset to one immutable message. PNG/JPEG/WebP/PDF uploads are capped at 5 MiB, use canonical base64, validate declared format headers and run the existing scanner. Non-test environments fail closed without the ClamAV daemon. Files use generated names and private modes, never caller-supplied paths. Conversation access is checked before scanning and again before commit; message, media metadata, attachment link and existing message audit intent are one transaction.

Retries retain message UUID, caption, MIME and SHA-256. Concurrent uploads serialize on the conversation; duplicates remove unused candidate files. Failed transactions remove their file only after a separate database read proves no asset committed. An uncertain COMMIT or unavailable reconciliation read retains bytes, rather than destroying a possibly committed attachment. Crash-created orphan reconciliation remains an operational requirement.

Downloads require current verified membership and authorized history, live message and clean/active media. Departed/restored members cannot download prior private-group files. Removed messages have no attachment metadata or downloadable bytes. Downloads verify size/checksum and send no-store, nosniff and attachment disposition. Generic profile-media routes refuse private-chat assets even for platform administrators. Global-scope moderators can access only a reported attachment through its case endpoint; private conversation history remains inaccessible.

Browser IndexedDB AES-GCM and Android Keystore-backed outboxes now persist immutable file payloads with captions and the original IDs. Total encoded queue budget is 8 MiB with at most 100 intents; each attachment is at most 5 MiB. Queue persistence failure sends nothing and preserves composition. Account/API binding, ordering, backoff, permanent-failure review, discard and logout purge apply to attachments. Browser file-read completion is bound to the original account/conversation. Android uses native system document pick/save dialogs without broad filesystem permission. Other mobile platforms have no picker implementation in this repository and remain unaccepted.

Local verification: API/admin typechecks and production builds, 143 API unit tests, 27 Playwright scenarios collected, original 260-row requirement validator passes. Added seven real PostgreSQL scenarios for concurrency, private/reviewer routes, restored history, tombstones, audit rollback, lost COMMIT acknowledgement, path and integrity failures; browser encrypted reload/lost-response/download scenario; Flutter queue and picker tests; Android encrypted real-API attachment lost-response recovery and original-byte download assertion.

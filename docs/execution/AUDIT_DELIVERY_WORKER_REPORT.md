# Scheduled durable audit delivery — 2026-10-10

Retained audit intents previously depended on later logout/role operations for delivery retries. AuditDeliveryService now starts a five-second background cycle outside isolated test environments, waits for migrations first, coalesces overlapping local ticks, limits each cycle to twenty eligible events and waits for in-flight work during shutdown. PostgreSQL row locks with SKIP LOCKED coordinate multiple API processes; no in-memory leader or new external queue is required.

Migration 049 retains a next-attempt timestamp. First failure waits thirty seconds, subsequent failures double the delay up to one hour, and ten failures exhaust automatic delivery. The schedule survives restarts. Old unscheduled pending/failed records remain eligible within the existing retry limit. Exhausted records remain stored for governed investigation; no reset, deletion or invented successful delivery occurs. Existing drain callers now respect eligibility and backoff as well.

Eligibility is locked before append work. A PostgreSQL savepoint rolls back a failed append, including an actual SQL error that aborts the inner work, while retaining the eligibility lock long enough to persist retry state in the same transaction. This prevents concurrent scheduled workers from spending the same retry window. Outbox-ID deduplication and the serialized append-only chain remain in force. A late failure update cannot turn an already processed record back into a failure. Retry timing uses the database failure-time clock, rather than the start of a potentially slow transaction. Failure metadata and warnings use fixed codes and record IDs, without copying downstream errors or event payloads.

The down migration refuses to discard an existing retry schedule; export and approved reconciliation are required before rollback. This does not replace production migration/rollback rehearsal or demonstrate an online index build at target scale.

Five unit cases cover test isolation, migration-before-timer ordering, local single flight, cycle recovery and graceful shutdown. Five PostgreSQL cases cover persisted backoff/restart/exactly-once recovery through the worker, real SQL/savepoint failure, overlapping worker ownership, bounded exhausted evidence, late-failure protection and rollback refusal. The prior logout-recovery test now explicitly makes its retained event due before asserting successful recovery. Exact-head CI must verify database/browser/native compatibility.

Production alert routing, oldest-backlog/failed-count monitoring, governed exhausted-event remediation, target-load/availability acceptance and full OTP request/failure/rate-limit audit coverage remain mandatory. No operational SLA, final acceptance, merge or production deployment is claimed.

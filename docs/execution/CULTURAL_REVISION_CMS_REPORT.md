# Governed cultural content revisions — 2026-10-08

This change adds durable CMS documents independently of legacy article rows and in-memory rule proposals. It does not activate cultural rules, supply religious approval, migrate legacy approvals or close HG-005 or any acceptance row.

## Implemented behavior

Migration 041 adds stable document slugs, retained numbered content revisions, explicit designated approvers, a current publication pointer and paginated decision history. Content managers (Super Admin, Central Admin, Cultural Historian) create drafts and new revisions. Replacing a draft archives it rather than deleting its content. Published revisions remain visible while a replacement is drafted/reviewed. Publishing an approved replacement marks the former publication superseded; archiving withdraws the current publication without deleting history.

An independent content manager endorses review. A central administrator explicitly designates an active phone-verified community account as representative, with a reason. The designated representative must be distinct from author and reviewer and explicitly approve the reviewed revision. Current author/reviewer/approver IDs, review/approval/publish timestamps and source provenance are retained. Publication rechecks both signers' active account and current role eligibility. Returning a pending revision to draft clears its current approvals; past decisions remain in the event journal. Designation snapshots are retained in decision and audit evidence.

Every write holds the document lock and compares the supplied document version; concurrent stale mutations receive 409. State changes, content revisions, decision evidence and audit intent commit in one transaction. Audit failure rolls back publication and evidence. Bodies accept only operation-specific fields; authenticated actors come from the existing database-backed JWT session guard. Undesignated members cannot read draft histories, decision reasons or management queues. Search returns only the current published revision, matching Nepali/English title/body and approved keywords using PostgreSQL simple text search, with a bounded first 50 results. Plain text is rendered through React/Flutter text widgets, not executable HTML.

The web culture page provides draft/revision forms, representative designation, review/return/approval/publication/archive controls, search, revision history and decision paging. A fixed `/login?next=/cultural` route allows currently verified community representatives and historians into their cultural workflow, through the existing authenticator screen; it does not grant administrator roles or accept arbitrary redirect URLs. Existing default admin login behavior is retained. Android/Flutter adds a signed-in culture reader and search with publication revision/provenance and refresh/error recovery. New cultural content updates are served from the API without a mobile release.

This feature does not satisfy the independent performance, disaster recovery, monitoring, infrastructure/provider or security release gates.

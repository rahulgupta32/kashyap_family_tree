# Genealogy invitation audiences and recipient evidence — 2026-10-08

Branch, generation-within-branch and verified-descendant audience selection now has a durable preview/confirmation workflow. This supplies bounded implementation evidence for INV-FR-004 and INV-FR-010. Authority-defined relationship groups remain unavailable: no draft Nata/Saino or cultural catalogue is activated or inferred. All frozen requirements remain mandatory and their signed acceptance remains open.

## Selection and privacy

The authenticated actor must currently be active, phone-verified and hold verified membership or administrative authority. Branch and generation selection require current membership in the selected branch or global administrative authority. Descendant selection requires the same authority in the ancestor's branch. Archived, minor-protected and private/immediate-family-only profiles are excluded, including intermediate graph nodes. Descendant traversal uses only VERIFIED BIOLOGICAL/ADOPTIVE parent links, deduplicates nodes to terminate cycles and excludes the ancestor from the recipient roster. Cross-branch descendants can be selected through visible verified links; event branch visibility, when chosen, independently restricts account eligibility.

Recipients must be active phone-verified accounts with verified roles and a matching approved claim: the account's Person link and the Person's claimed owner must agree. Branch/generation recipients need current matching branch membership or global administrative authority. Preview responses expose only eligible account/Person IDs and display names, never phone or contact details. Selection inputs are strictly whitelisted and UUIDs canonicalized. Selection caps are 1000 visible Persons, 10000 evidence edges and 100 eligible accounts. Oversized selections fail rather than truncate. Queries have a five-second statement timeout; production-scale latency acceptance is still required.

Event visibility is separate from invitation selection. Admin explicitly chooses visibility; mobile uses INVITED_ONLY when a genealogy audience is chosen. A public/community event may be visible beyond its invitation roster. Both clients show the server-resolved names/count and require confirmation. Changed selection criteria, session changes, failed confirmation and expired previews clear/require a new preview. Mobile ancestor searches and admin ancestor searches retain epoch guards against stale responses.

## Durable confirmation and reconstruction

Migration 043 stores a ten-minute, actor-bound preview with canonical criteria, versioned visibility/membership policy, Person IDs/versions/branch/generation/visibility state, verified parent-edge IDs/endpoints/types, eligible account/Person mappings and role assignments. It retains PostgreSQL snapshot context and capture time. Names and contact details are excluded from this evidence. A server-side SHA-256 fingerprint binds the selection basis; it is not a signature from a cultural authority.

Confirmation requires the exact preview actor, criteria and visibility scope, re-resolves the current basis in a repeatable-read transaction and rejects changed genealogy/eligibility, expired previews, reused previews or empty audiences. Concurrent confirmation of the same preview produces one committed event; serialization conflicts become reload/preview conflicts. Preview creation uses serializable isolation and a per-account lock with a cap of 20 active previews. Event invitations, immutable consumed evidence, event revision, audit intent, recipient notification records and reminder scheduling commit together. Audit failure rolls back all of them, leaving an unused preview available for retry.

Each revision retains the relevant preview pointer. Changing derived recipients requires a new confirmed preview and event version; existing recipients are not silently recomputed when genealogy changes. Replacement preserves earlier evidence and revokes removed invitations. Metadata-only edits retain the original frozen audience. Changing visibility without replacing/explicitly converting a derived audience requires a new preview. Delivery eligibility is checked again by the existing dispatcher; selection evidence does not authorize delivery to suspended accounts or bypass event visibility.

A database trigger forbids evidence mutation/deletion and allows only initial consumption fields to be added once. Rollback migration refuses to drop any retained evidence. Organizer/scoped-admin event history checks current verified membership and original selection-branch authority, records durable read intent, and returns the retained basis with preview/send context. Preview and history responses use private/no-store headers. Ordinary invitees receive neither this basis nor the organizer's selector in event details.

# Bounded complete community comment browsing

Authenticated GET /community/posts/:id/comments/browse returns at most 50 newest-first comments with a nextBefore UUID cursor. A locked current-post visibility check applies on every page. The cursor must refer to a retained comment in the same post; deleted cursor rows remain usable as boundaries. PostgreSQL compares the original created_at and UUID tuple directly, preserving microseconds and deterministic tie ordering. The partial post/timestamp/ID index in migration 036 supports bounded reads; rollback drops only the index. The legacy array endpoint remains unchanged for compatibility.

A same-post live-parent join includes parentContent even when the parent lies outside the loaded page. Deleted/unavailable parents return null. This exposes only context already governed by the same post visibility; it does not provide access to another post or deleted content. Replies remain a flat newest-first conversation with explicit parent context, not a recursive tree.

Web and Flutter use the paginated endpoint, append nonduplicate older results, reset to latest, show loaded counts and disable exhausted/loading navigation. Successful comment submissions reload latest so the new comment is reachable even in a long conversation. Failed reads clear previously loaded comments and offer latest retry. Web session changes invalidate old reads and clear drafts/targets. Reply/cancel controls continue to use the current session.

Regression coverage adds a PostgreSQL HTTP case traversing 206 retained comments beyond the old 200 cap, including 205 microsecond timestamp ties, concurrent newer insertion, deleted boundaries, deleted-parent suppression, malformed/foreign/missing cursors and current access/deletion checks. Browser coverage creates a 53-comment conversation and exercises older/exhausted/latest navigation. A new mocked Flutter test verifies cursor carry-through, append/exhaustion, parent context and latest reset; the existing reply test uses the paginated contract.

Pages are current reads, not an immutable cross-request snapshot: deletion, backdated or delayed commits can change results. Exact-head CI evidence is recorded in PR #5.

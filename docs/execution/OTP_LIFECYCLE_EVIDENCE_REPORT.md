# Durable OTP lifecycle evidence and delivery visibility — 2026-10-10

OTP request and verification service operations now write an anonymous server-generated attempt ID into the PostgreSQL audit outbox before normalizing/reserving a challenge, incrementing counters, dispatching SMS or consuming an OTP. Failure to acknowledge this initial write returns a bilingual 503 before those side effects. No phone number, phone hash, OTP, Redis challenge/session ID, token, device label, provider response or exception text is copied into the new event payload. Request IP is restricted audit metadata; these records are not claimed fully anonymous. Successful login still retains governed actor/session/IP/user-agent metadata.

Request completion records SMS_ACCEPTED only when the provider reports acceptance, without claiming actual delivery. Rejections retain an allowlisted machine reason for invalid phone, cooldown, request rate, incorrect/expired/exhausted OTP, account suspension/deletion, dependency outage or SMS failure. Unknown failures use a fixed generic code. Verification success links the attempt ID to LOGIN inside the same transaction as its session, preserving the previous no-credentials-on-unconfirmed-commit guarantee. A failed verification records its rejection outcome before returning the existing business error; if evidence acknowledgement fails, the response is safe 503 instead.

Redis, PostgreSQL and SMS do not form a distributed transaction. A crash or outcome-write outage can leave an acknowledged attempt without a terminal outcome, even after a side effect. A lost acknowledgement can leave actual committed outcome or session evidence while the client receives no credentials. The application does not invent a rollback or automatically repeat SMS, OTP consumption or credential creation. Requests with an unconfirmed SMS outcome receive no challenge ID and may need the existing cooldown before a fresh request. Verification already consumed before a downstream failure requires a fresh OTP. Retained attempts are available for governed investigation; this change does not supply automatic incident closure.

SMS exceptions now pass through the same identity-checked Redis cleanup/backoff path as negative provider results. The authentication-service SMS diagnostic contains a fixed code, without phone/provider-error text. The IP request counter increment and expiry now execute in one Redis Lua operation, including repair of a pre-existing counter without TTL; healthy counters keep their existing window.

GET /audit/delivery is restricted to current central/super-administrator authority with existing MFA/session enforcement, returns no-store aggregate counts and fixed unavailable responses, and exposes no event IDs, identities, IPs, payloads or raw errors. A single PostgreSQL snapshot reports pending, due, delayed, failed and exhausted counts, oldest pending/due age, and attempts older than ten minutes without a retained outcome or linked LOGIN. The ten-minute investigation threshold is not an authentication timeout or delivery SLA. Worker timestamps, lifecycle, current in-flight state and last batch counts describe only the responding API process; queue aggregates cover all processes. An outbox selection outage now propagates to the worker rather than appearing as an empty successful cycle.

The bilingual administrator panel refreshes the aggregate snapshot, clears old data when refreshing or receiving an error, aborts superseded/unmounted requests, and resets its instance for account/role changes. It is hidden from branch reviewers and members. It adds no reset/delete/replay control for exhausted records. Migration 050 adds partial correlation/age indexes; its down migration drops only indexes and preserves evidence. Target-scale query/index migration performance remains unproven.

Regression evidence includes initial-write/no-side-effect failures, OTP failures and redaction, thrown SMS cleanup, outcome outage/lost acknowledgement, real Redis rate-window repair, pending/due/delayed/exhausted boundary counts, unresolved-attempt matching, process heartbeat failures/recovery, central/MFA/role-revocation permissions, unavailable responses, and browser status/error behavior. Local checks and exact-head CI results are recorded in PR #5; collection of browser tests is not their execution.

AUTH-FR-011, AUD-FR-001/005 and NFR-OBS-001/002 remain partial/open. DTO/guard/edge rejections outside the service, all refresh/revocation lifecycle outcomes, production SMS receipts, authority-approved retention/deletion/export, exhausted-event remediation, fleet metrics/alert routing/on-call drills, exact load/availability and the remaining frozen acceptance are not demonstrated by this checkpoint. The public authentication evidence path also requires production ingress abuse controls and a measured audit-capacity budget. Existing five-second/twenty-event delivery limits remain bounded and are not a throughput SLA. All 260 acceptance rows remain open; no merge or deployment is performed.

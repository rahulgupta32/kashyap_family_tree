New authenticated private/no-store POST /me/claim-evidence accepts only MIME/base64, one limited evidence category (family_photo/event_invitation/clan_record) and explicit evidence-notice acknowledgement. It reuses the existing bounded MIME/magic/base64/image-inspection/malware/private-storage pipeline. Clean evidence gets an independent private-profiles asset/checksum and audit-only PROFILE_CLAIM_EVIDENCE_UPLOADED event; it never replaces avatar or enqueues profile derivatives. Infected/failed scanner outcomes remain inaccessible and return no attachable result. Upload audit is excluded by existing notification category policy. Labels cannot prove image semantics: moderation/privacy/legal controls and actual authority to share content remain required. This is not automated detection or approval of government-document content.

Initial/correction/dispute attachment validation now rejects non-arrays, more than five per mutation, malformed/duplicate IDs, unsupported labels, oversized descriptions and unknown fields before linking. Current ownership/private bucket/CLEAN/retention checks stay authoritative. Existing legacy supported metadata labels remain compatible; the new picker exposes only the limited upload categories. Removing an unsubmitted selection does not delete retained bytes. Failed or abandoned upload attempts may leave distinct private assets; existing write journals/orphan/retention operations remain responsible. Upload is not claimed exactly once.

Key is optional for backward compatibility; legacy unkeyed callers retain existing active-claim controls, not guaranteed keyed replay. No receipt expiry is invented.

Native claim form now supports the existing native image picker, explicit collection notice, limited category choice, up to five successful assets, selection removal and exact evidence payload. It freezes a captured submission/body/UUID after first send; retries preserve that identity. Busy/retained callback, session/service/target change and disposal guards stop stale submissions/results and clear private state. Generic errors hide server/scanner diagnostics; response displays actual returned review status without implying approval. Pending claim identity is route-memory only; secure cross-process restoration, safe pending-intent resolution and correction/resubmission/dispute attachment interfaces remain open. This does not complete the full claim lifecycle or physical-device acceptance.

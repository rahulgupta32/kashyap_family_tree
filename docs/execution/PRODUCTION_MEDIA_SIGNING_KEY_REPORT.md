# Production media signing-key gate

A source audit found that `ProfileService` selected the known compiled development HMAC key when `MEDIA_HMAC_SECRET` was missing, including production. Media authorization still required the current authenticated owner/administrator; this finding is a missing production signing-credential control, not a claim that HMAC alone permitted anonymous access.

The constructor now uses a fail-closed selector. Production requires a configured key of at least 32 UTF-8 bytes, without leading/trailing whitespace, and rejects the known development fixture. Startup diagnostics never include the key. Test/development fallback remains available for fictional fixtures. Provision independent managed random material and reviewed rotation/recovery before production; length validation alone does not prove entropy or managed storage. Existing media ownership/quarantine/retention checks and signature asset/user/expiry binding remain intact. No key or provider credential is generated or committed here.

Ten focused Jest regressions passed locally, including actual production service construction failure and real HMAC signing/verification with selected key and fixture-signature rejection. Shared packages compiled and API TypeScript checking passed using the existing cached dependencies directly. The container's pnpm wrapper is 11.25.0 and rejected the pinned >=9.15.9<10 engine; no dependency install or lock change was accepted. Exact-source CI uses pnpm9.15.9 and must independently run the normal frozen install/build/full suites.

Source files: `services/api/src/common/utils/media-hmac.config.ts`, `services/api/src/modules/profile/profile.service.ts`, `services/api/test/media-hmac-config.spec.ts`, `services/api/.env.example`. This bounded control advances MEDIA/PRIV/NFR-SEC readiness; it does not close managed-secret/TLS/independent security/signing/production acceptance gates. All frozen acceptance rows remain OPEN. No merge/deployment.

1. How to use this specification
Every row is a mandatory design, implementation and test consideration. Developers must implement the expected behaviour and QA must convert the Given/When/Then statement into automated or controlled manual evidence. Product, privacy, security, genealogy and cultural authorities remain responsible for domain approval. Newly discovered cases are added through versioned change control; absence from this catalogue never authorizes unsafe behaviour.
Server-side authorization overrides client display state.
No error may silently corrupt, overwrite, duplicate or expose authoritative data.
Retry is automatic only when bounded and idempotent.
Unapproved cultural rules use neutral/disabled behaviour.
Sensitive error responses are generic to the user but traceable through safe correlation and audit.
All user-facing final messages require professional Nepali-language review before production.
2. Cross-cutting exception contract
Concern
Frozen rule
Validation
Reject invalid input before mutation and return stable field/error codes.
Authorization
Evaluate current server-side role, scope and privacy at execution time.
Concurrency
Use version/idempotency controls; do not use silent last-write-wins for governed data.
Transactions
Commit all authoritative changes atomically or preserve a recoverable, explicitly incomplete state.
Audit
Record safe attributable evidence for governed and privileged outcomes.
Offline/retry
Never display success before server confirmation; preserve safe drafts and reconcile on reconnect.
Localization
English and Nepali messages must convey the same action and consequence.
Accessibility
Error focus, announcements, contrast and recovery action must remain usable.
Observability
Every unexpected failure has correlation, metric and operational ownership.
Recovery
Provide retry, correction, appeal, reassignment, rollback or support path.
